# Audit — RFCs 0002 and 0003 vs. current code on the kayakgen package

Date: 2026-05-10
Context: follow-on to the RFC 0007 package extraction. RFCs 0002 and
0003 had partial implementation already on `main` (commits
`27a8753`, `4ff20a1`, `64305fc`); after the desktop GUI moved into
`kayakgen.ui.desktop`, this audit catalogs which acceptance criteria
are already satisfied on the new package and which remain.

## RFC 0002 (GUI Usability) acceptance criteria

| # | Criterion | Status | Where |
|---|---|---|---|
| 1 | Slider labels fully visible at 1440×900 | DONE | `kayakgen/ui/desktop.py:_build_sliders` (`s.label.set_position((0.5, -1.8))` with `set_horizontalalignment("center")` plus `GridSpec(left=0.38)`) |
| 2 | Fast slider drag — at most one queued 3D render | DONE | `KayakGUI._3d_timer` (QTimer, 80 ms, single-shot) wires `_flush_3d`; `_on_change` only `start()`s the timer |
| 3 | 3D View button feedback within 100 ms | DONE | `_on_open_3d` sets the button label to "Opening…" and forces a draw before constructing `PyVistaWindow` |
| 4 | Derived metrics block updates live | DONE | `_refresh_metrics` runs on every slider tick. As of RFC 0007 §4, it consumes `evaluate_hydrostatics` rather than the old formula envelope |
| 5 | Arrow keys nudge the last-moved slider | DONE | `_on_key` + `_track_slider` |
| 6 | Generate STLs opens a save dialog | DONE | `_on_generate` uses `QFileDialog.getSaveFileName` and writes `<stem>_hull.stl` and `<stem>_deck.stl` |

Additional 0002 work landed in 0007b: the `pyvista_view.py`
window-title linkage updates on `update_mesh` (`PyVistaWindow._update_title`).
3D-preview station count is reduced to 80 (vs. the 150 used by the
STL exporter) inside `kayakgen/ui/pv_window.py:_build_scene`.

**Closed.** No remaining 0002 work for the desktop GUI.

## RFC 0003 (Layout + Station View) acceptance criteria

| # | Criterion | Status | Where |
|---|---|---|---|
| 1 | No slider/button overlap with plot axes at 1440×900..2560×1440 | DONE | `GridSpec(left=0.38, right=0.97, ...)` + slider axes constrained to `x ≤ 0.33` |
| 2 | Top-right panel labelled "Sheer Plan" with legend | DONE | `update_plots` sets title "Sheer Plan" and labels keel/deck/waterline |
| 3 | Cross-section updates as station slider moves | DONE | `_on_station_change` writes `self.station_x`, `update_plots` re-uses it via `geom.section(self.station_x, …)` |
| 4 | Cursor line on plan + sheer | DONE | `axvline(self.station_x, color="crimson", ls="--")` on both axes |
| 5 | Cross-section title shows current x and percentage | DONE | `f"Cross-Section x = {…:+.2f} m ({abs(pct):.0f}% {side})"` |

The `station_x` clamp on length change is still in `_on_change` —
`np.clip(self.station_x, -half_L, half_L)` keeps the cursor inside
the new domain.

**Closed.** No remaining 0003 work for the desktop GUI.

## Items intentionally *not* retargeted

- **RFC 0006 §"GUI changes" — class radio dropdown.** Deferred from
  the 0006 PR with a note that it would be retargeted here. Adding
  it in this commit (see below).
- **RFC 0002 §"Open Questions" — debounce auto-tuning, metrics
  panel height knob, QTimer dependency.** All three are speculative;
  the current 80 ms debounce is fine for the kayakgen panel densities
  the tests exercise. Revisit only if a user reports lag.
- **Validation banner above the 3D view (RFC 0006 §6).** The metrics
  panel already shows the class label and an out-of-class fallback
  string. A separate dismissable yellow banner would duplicate that
  signal in a noisier way. Left out unless a user asks.

## Web frontend gap (separately tracked under RFC 0008)

The web app has slider parity with the desktop, the same metrics
panel, and `Reset` / `Share` / `Export Hull/Deck STL` toolbar buttons.
The matplotlib panels (cross-section, sheer plan, plan view) are not
yet ported to the web — `trame-matplotlib` makes that straightforward
once we decide the spread between an additional Vega/Plotly stack and
keeping matplotlib. Out of scope for this audit; tracked under the
follow-on RFC 0009 the 0008 PR description points at.
