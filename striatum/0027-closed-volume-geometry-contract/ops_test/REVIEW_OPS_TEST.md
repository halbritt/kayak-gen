## Findings

### O-001 - Closed-volume contract and synthetic fixtures are not implemented

RFC 0016 requires a closed-volume body format, closure policy metadata, diagnostics that reject open surfaces, and tests for valid closed, open, and nonmanifold synthetic bodies. The current implementation remains the RFC 0010/0015 open-surface mesh-package and dispatch slice: `write_mesh_package` emits `hull.json`, per-part quality reports, and separate `hull.stl`/`deck.stl` surfaces, while the watertight profile is blocked with warnings that the package writer emits separate open surfaces (`kayakgen/eval/mesh_package.py:83`, `kayakgen/eval/mesh_package.py:154`). The tests cover generated `Hull()` packages and dispatch gating, but do not define or exercise a synthetic closed body, open body, or nonmanifold body fixture (`tests/test_mesh_package.py:33`, `tests/test_cfd_jobs.py:109`, `tests/test_cli.py:136`).

Required action: add the RFC 0016 closed-volume model/manifest/diagnostics boundary as a separate artifact from display STL and mesh-package surfaces, then add deterministic synthetic valid/open/nonmanifold fixtures that prove closure acceptance and rejection before claiming workflow 0027 acceptance.

### O-002 - CFD readiness gating trusts manifest claims without revalidating diagnostic evidence

`prepare_local_job` loads `manifest.json` and `_validate_mesh_package` checks the declared solver profile, declared readiness level, and existence of referenced files (`kayakgen/eval/cfd/jobs.py:257`, `kayakgen/eval/cfd/jobs.py:426`). It does not parse the referenced `quality.*.json` diagnostics or independently verify boundary/nonmanifold counts before accepting a solver profile. A malformed or hand-edited manifest that declares `watertight_solid_resistance_v1` plus `cfd_ready` and points at existing open-surface artifacts would pass the current readiness comparison (`kayakgen/eval/cfd/jobs.py:431`, `kayakgen/eval/cfd/jobs.py:439`). That leaves a false solver-readiness path precisely where workflow 0027 is trying to harden closed-volume semantics.

Required action: make dispatch readiness validation evidence-based for watertight profiles. At minimum, parse the referenced quality/closed-volume diagnostics and reject manifests whose boundary, nonmanifold, closure-policy, or profile evidence does not satisfy the selected solver profile. Add regression tests with a forged `cfd_ready` watertight manifest over current open artifacts and require `cfd prepare` to reject it.

### O-003 - Mesh-package diagnostics are not written under the selected solver profile

`write_mesh_package` accepts a `solver_profile`, but each quality report is generated by `diagnose_mesh` without passing or attaching that profile (`kayakgen/eval/mesh_package.py:89`, `kayakgen/eval/mesh_package.py:103`). The serialized `MeshDiagnostics` therefore has `solver_profile=None` even when the manifest is for `watertight_solid_resistance_v1` (`kayakgen/eval/mesh_diagnostics.py:82`, `kayakgen/eval/mesh_diagnostics.py:142`). The manifest-level readiness warning is conservative, but the per-part diagnostics are not profile-specific evidence and cannot support future deterministic gating or audit trails.

Required action: either attach the selected mesh solver profile to the written quality reports or add a separate closed-volume diagnostics report that is explicitly profile-scoped. Tests should assert profile identity in serialized diagnostics for open-surface and watertight-blocked packages.

### O-004 - CLI failure-mode coverage is too narrow for the new geometry contract

The CLI tests cover successful mesh-package creation, watertight-profile downgrade wording, unavailable dispatch status, and watertight dispatch rejection (`tests/test_cli.py:120`, `tests/test_cli.py:136`, `tests/test_cli.py:161`, `tests/test_cli.py:201`). They do not cover unknown solver-profile names, missing `manifest.json` in an existing mesh-package directory, missing referenced artifacts, malformed manifests, non-positive CFD inputs through the CLI, or future closed-volume check/status wording. Those cases are handled or partially handled in lower-level code (`kayakgen/eval/cfd/jobs.py:416`, `kayakgen/eval/cfd/jobs.py:453`, `kayakgen/eval/cfd/jobs.py:460`, `kayakgen/eval/cfd/jobs.py:521`), but workflow 0027 needs CLI-level rejection/status wording to avoid users interpreting solver hooks as real solver readiness.

Required action: add CLI regression tests for malformed/missing mesh-package artifacts, unknown mesh and CFD solver profiles, invalid CFD numeric inputs, and closed-volume diagnostic rejection wording. Keep the existing raw/unvalidated wording checks, and add equivalent checks for any closed-volume CLI surface.

## Positive Coverage

The current package and dispatch slice is directionally conservative. Open wetted-surface packages are labeled `cfd_surface_candidate`, watertight-profile packages stay below `cfd_ready`, unavailable solver profiles report `unavailable`, mock failed commands record `failed`, and CLI status includes raw/unvalidated wording (`kayakgen/eval/mesh_package.py:168`, `kayakgen/eval/cfd/jobs.py:157`, `kayakgen/eval/cfd/jobs.py:167`, `kayakgen/eval/cfd/jobs.py:177`, `kayakgen/cli/main.py:178`, `kayakgen/cli/main.py:198`, `kayakgen/cli/main.py:223`).

That is acceptable as an RFC 0010/0015 continuation, but not sufficient for workflow 0027's closed-volume geometry contract.
